# Maintainer Disclosure Checklist

Use this checklist before sending a private security report to an open-source
maintainer.

- [ ] The target project, affected component, and tested version are identified.
- [ ] Testing was performed only in owned, local, CTF, or explicitly authorized
      environments.
- [ ] The report uses the project's preferred private security channel.
- [ ] Impact is stated conservatively and does not exceed observed behavior.
- [ ] Reproduction material is minimal, defensive, and sent privately only when
      appropriate.
- [ ] The report includes expected behavior and suggested validation criteria.
- [ ] Public issue trackers are avoided for non-public vulnerabilities.
- [ ] No credentials, cookies, sessions, private logs, or third-party data are
      attached.
- [ ] Any requested public credit name is explicit and accurate.
